# Composition and source map

Source role: Three Layers projection of the [ecosystem composition owner](https://github.com/xavdp-pro/shaper-ecosystem/blob/main/chapters/10-COMPOSITION.md).
Terms: [independent glossary](https://github.com/xavdp-pro/shaper-glossary/blob/main/TERMS.md).

## Intention

The human–AI tandem connects purpose to useful systems through readable ownership
and relationships. Agents resolve each task to its exact governing sources,
required dependencies, permitted capabilities and implementation owner.

## Two complementary views

| Composition | OS responsibility | Runtime responsibility | Workspace responsibility |
|---|---|---|---|
| Component | Purpose and applicable laws | Focused function, interface and state | Useful inspection or controls |
| Generic stem cell | Reusable composition intention | Generic execution functions | Shared interaction contracts |
| Specialized cell/service | Domain intent and laws | Base plus one or more domain units | Domain work surfaces |
| Logical space | Membership and jurisdiction principles | Owned membership and relationships | Authorized connected context |
| Fractal | Scoped governance and delegation | Governors, makers, workers and observation | Tandem piloting across scopes |

Infrastructure supplies placement and technical operations. OS, Runtime and
Workspace responsibilities apply at every composition scale. Logical membership,
dependency, authority and placement retain distinct relation types.

## Ownership and task route

For a task, identify purpose and jurisdiction, then follow the exact source route:
governing intention/laws → required interface dependencies → implementation owner
and capability → authorized operation → attributable result. Integration prose
links to owning law; its interpretation remains identifiable.

The ecosystem owner maintains composition and cross-project relations. The
glossary owns definitions and aliases. Three Layers owns the responsibility
projection. Component, base and domain products own their implementations.
Each new product or mental-source repository has a distinct companion
`-lab` work repository. Common public mental sources connect to privately owned
user implementations, configuration, data and work through permitted references.
