# Class, specialization and instance

Source role: Three Layers projection of the [ecosystem identity contract](https://github.com/xavdp-pro/shaper-ecosystem/blob/main/chapters/20-CLASS-INSTANCE.md).
Terms: [class](https://github.com/xavdp-pro/shaper-glossary/blob/main/TERMS.md#class)
and [instance](https://github.com/xavdp-pro/shaper-glossary/blob/main/TERMS.md#instance).

## Intention

Reusable forms evolve coherently while instances preserve identity, state and
jurisdiction. The tandem places a change with its proper source owner.

## Identity projection

A class has a stable ID, owner, version and interface/configuration contract.
A specialization binds a base version to one or more domain units and permitted
variation. A specialized cell is a service. An instance binds that reusable form
to a jurisdiction, configuration and owned application state. Placement identifies
the resources currently executing the instance.

OS governs change and authority. Runtime maintains identities, version bindings,
state and operations. Workspace presents the selected form and its permitted
actions. A reusable specialization can itself be owned as a class.

## Change interface

Instance configuration follows its selected class contract. Reusable behavior
changes belong to the class owner and produce an adoptable version. Instance
identity persists across placement changes. Schema and interface transitions
preserve historical meaning and consumer compatibility through explicit mappings.

A customer installation creates an instance of a selected form. Repository names,
display terms and deployed instance IDs each retain their distinct role.
