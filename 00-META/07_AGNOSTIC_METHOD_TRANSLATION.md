# Agnostic Method Translation

## Status

Architectural and pedagogical policy. It governs how SHAPER adopts useful
conceptual tools from outside sources.

## Purpose

SHAPER may learn from any source that helps people and agents observe,
coordinate, decide, act, verify and improve. A source is never adopted as an
authority. Its useful structure must first be translated into clear, ordinary
language that a person can question, test and change.

The result is a method, not an affiliation, belief system, hierarchy or claim
about people.

## Translation rule

A concept may enter SHAPER only when all of the following are true:

1. It has a plain-language name and definition.
2. It identifies an observable situation, a decision, an action or a result.
3. It can be illustrated by a real working example.
4. It names what could go wrong or be misunderstood.
5. It has a proportionate verification method.
6. It does not create authority, permission or obligation by its name alone.
7. It can be revised or removed when evidence shows it is unhelpful.

Permissions remain derived from identity, role, object, context, policy and
explicit mandate. A useful concept never grants a person or agent additional
power.

## A reusable project alignment stack

When a project needs a complete view from intention to outcome, SHAPER may use
this neutral sequence:

```text
desired outcome
  -> operating purpose
  -> durable principles
  -> strategy
  -> coordinated programme
  -> bounded project
  -> immediate action
  -> desired operating scene
  -> indicators
  -> useful delivered outcome
```

The sequence is a coherence check, not a chain of unquestionable commands. A
weak indicator, an ineffective action or an unexpected result is a reason to
revisit the level above it.

## Desired operating scene

A desired operating scene describes how work should look when it is working
well. It is concrete enough to answer:

- who is involved;
- what each person or agent can observe and do;
- what data, permissions and safeguards are required;
- what happens in ordinary, exceptional and recovery cases;
- what result is useful outside the implementation team; and
- what evidence will show that the scene works.

It is then compared with the current operating scene. The difference becomes a
bounded gap list, followed by minimum viable work and evidence gates.

## Evidence path

Every significant piece of work remains distinguishable as:

```text
intended -> specified -> implemented -> tested -> deployed -> observed -> accepted
```

No later state is inferred from an earlier one. A passing local test is not a
deployment; a running service is not user acceptance.

## How this supports human-agent work

The method gives a shared way to ask useful questions without forcing one
person's vocabulary on everyone else:

- What outcome are we trying to make real?
- What is true now?
- Which gap matters first?
- Who may decide or act?
- What would prove the result?
- What did reality teach us after the action?

An agent may organize, compare, propose and test within its mandate. A human or
other authorized actor remains responsible for decisions that require their
authority.

## Guardrails

SHAPER does not import external ranks, claims about human nature, spiritual
claims, organizational authority or mandatory practices into its product,
architecture, interfaces or documentation. It keeps only structures that can be
explained in ordinary language, applied voluntarily and checked against reality.
