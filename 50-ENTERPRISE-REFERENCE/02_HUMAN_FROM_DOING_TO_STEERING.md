# Enterprise OS — Human Guide
## From doing to steering

Enterprise OS should feel familiar before it feels powerful.

A new user should first see a believable company already operating with realistic data.

The system must communicate:

> **You can work manually as before. Nothing forces automation. But everything is already connected if you want to accelerate.**

---

# Level E0 — Familiar work

The user can:

- browse customers;
- find products;
- see stock;
- read emails;
- create tasks;
- read documents;
- inspect orders;
- use search.

No agent required.

Goal: trust through familiarity.

---

# Level E1 — Ask Helm

The user asks Helm:

- “Find this customer.”
- “Show me their latest order.”
- “Summarize this supplier email.”
- “Prepare a quote.”
- “Create a task.”
- “Find the contract.”
- “Show me the best-selling product.”

Goal: understand that natural language is another interface to the same business graph.

---

# Level E2 — Delegate once

Examples:

- “Prepare the invoice for customer X.”
- “Create the updated price ranges from this supplier file.”
- “Call this customer.”
- “Prepare the follow-up email.”

Helm or Maestro executes bounded work and leaves traces.

Goal: experience delegation.

---

# Level E3 — Pilot

The user starts asking:

- “What deserves my attention?”
- “What changed?”
- “Which customers are most profitable?”
- “Which products are likely to run out?”
- “What should we improve?”
- “Which recurring work could be automated?”

Goal: move from execution to steering.

---

# Level E4 — Standing mandate

A repeated process can run under a standing mandate:

- scheduled;
- event-driven;
- approval-based;
- automatic within the mandate, with its scope, owner, exceptions, STOP and review.

The human chooses, and the mandate says where automation stops.

Goal: scale without losing governance.

---

# Level E5 — Shape the environment

The pilot adds, configures or removes a feature the class offers, taken through
tests and counter-view, applied, then rolled back cleanly if needed.

Goal: the organization shapes its own tool without leaving its jurisdiction.

Level names follow the pilot levels of SHAPER OS V1.14 Rule 37 and the missions of
[the future owner journey](09_FUTURE_OWNER_AND_TESTER_JOURNEY.md) (aligned
17 September 2026).

---

# Decision traceability

When a meaningful operating rule changes, the system should be able to answer:

- Who decided?
- When?
- Why?
- Who was informed?
- What changed?
- Did it work?
- Is the decision still valid?

This is operational memory.

---

# Pedagogical maturity

Do not gamify heavily.

A light maturity indicator can show which concepts the user has already encountered:

- connected data;
- natural-language querying;
- delegated execution;
- decision traceability;
- monitored automation;
- rollback;
- operational observability;
- proactive optimization.

This is not a score of intelligence.

It is a map of capabilities the user has learned to use.

The same map, proven rather than displayed, is **pilot training**: guided missions in a formal demo universe validate each pilot level before Helm executes that level in production. See the [future owner journey](09_FUTURE_OWNER_AND_TESTER_JOURNEY.md#pilot-training-proving-each-level). It uses missions, never points or rankings.
