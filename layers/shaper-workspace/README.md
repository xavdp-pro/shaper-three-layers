# Shaper Workspace (bootstrap snapshot — not canonical)

> **Redirect:** [`30-SHAPER-WORKSPACE/`](../../30-SHAPER-WORKSPACE/) and [`layers/README.md`](../README.md).

**Layer type:** human operating environment and application surface.

Shaper Workspace gives each person and agent the correct view, tools, context, and controls for their role while preserving Runtime authorization, traceability, and evidence.

## Initial capability map

- role-based home spaces and organization navigation;
- unified objects, search, activity, notifications, and acknowledgements;
- human-agent conversations and delegated-action queues;
- user and administrator operating modes;
- CRM, products, sales, purchasing, inventory, accounting, documents, email, chat, projects, support, calendar, and telephony;
- dashboards for state, tendency, tension, health, integrity, and trust;
- explanations, confirmations, reversibility, STOP, and escalation.

## User / administrator separation

User and administrator experiences may be distributed as distinct applications for security and clarity, while remaining parts of the same Workspace layer. The architectural invariant is capability separation and explicit authorization—not a mandatory packaging choice.

## Boundary

Workspace does not become the source of truth merely because it displays or edits an object. It operates through Runtime contracts and must expose meaningful evidence of actions and results.
