# Shaper Runtime — Human Foundations
## What keeps your organizational world alive when the screen changes

You do not normally “use” the Runtime directly. It is the part that makes the Workspace durable and trustworthy.

## 1. Imagine changing computers

You use Shaper on Windows today and buy a Mac tomorrow.

After installation, enrollment and authentication, the system can restore your authorized work environment because the important truth did not live only on the old desktop.

That durable layer is the Runtime.

## 2. Identity

Runtime knows who or what is acting:

- person;
- agent;
- service;
- device.

A visible button does not create authority. Runtime checks whether the actor is allowed to perform the action in the current context.

## 3. Permissions are more than “admin/not admin”

A person may be allowed to read customers, create quotes and not see company-wide margins.

An agent may be able to prepare a payment but not submit it.

The Runtime combines roles, object/context rules, explicit capabilities and mandates.

## 4. Files become connected objects

A contract is not only `contract.pdf` in a folder. It can be connected to:

- customer;
- people;
- tasks;
- dates;
- decisions;
- versions;
- permissions;
- search/RAG knowledge;
- audit history.

You can still browse folders. The deeper model allows you to find the contract by meaning and context.

## 5. Import instead of permanent host attachment

A normal workflow can be:

```text
choose file on computer
→ import into Shaper
→ it becomes a governed object
→ work continues inside the organization context
```

Shaper does not need unrestricted permanent access to every folder on the host.

## 6. Search

Search can combine exact names, content, structured fields and semantic meaning — but only across data you are authorized to see.

## 7. Events and history

When important things happen, Runtime records enough context to answer questions such as:

- Who acted?
- What changed?
- Under which instruction/mandate?
- Which object was affected?
- What happened afterward?

This is operational memory.

## 8. Agents are actors too

Agents do not receive magical universal access. They have identities, scopes and capabilities.

A useful system can say:

> “The sales agent can read this contract but cannot export it.”

## 9. Security

Most local data can remain encrypted at rest. A client may hold only a bounded encrypted cache instead of a complete copy of the company's storage.

Security does not rely on “secret code.” It relies on keys, identity, isolation, policy, audit and recovery.

## 10. Offline modes

Different deployments can choose:

- online-only/minimal cache;
- hybrid offline working set;
- full local sovereign Runtime.

The user experience can remain similar even though the physical topology differs.

## 11. What happens when two people change the same thing?

The Runtime must know there is a conflict. Some data can merge automatically; some requires a person or agent to compare versions.

It should not silently overwrite meaningful work without a defined rule.

## 12. Why this is separate from Workspace

Workspace is what you see.

Runtime is what preserves:

- truth;
- history;
- rights;
- relationships;
- secure data;
- agent state;
- recoverability.

This separation is what makes the Workspace portable.

## Success

A good Runtime is mostly invisible. You notice it when switching device is easy, search understands context, agents respect boundaries, history makes sense, and recovery does not depend on finding files on someone's old laptop.
