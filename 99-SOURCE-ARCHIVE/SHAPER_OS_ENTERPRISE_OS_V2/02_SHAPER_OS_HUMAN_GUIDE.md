# Shaper OS — Human Guide
## Multi-level understanding

Shaper OS should not require every human to understand the entire kernel.

The same system can be explained at several depths.

---

# H0 — User

A user needs to know:

- what the system helps them do;
- what they are allowed to do;
- what happened after an action;
- where to find the result;
- how to stop or report a problem.

Mental model:

> **I ask. The system acts within my rights. I can see what happened.**

---

# H1 — Operator

An operator also understands:

- tasks;
- notifications;
- status changes;
- shared objects;
- traceability;
- context links;
- acknowledgment;
- escalation.

Mental model:

> **Work is connected. I should not have to search for the context of an alert.**

---

# H2 — Manager

A manager understands:

- decisions;
- delegation;
- responsibility;
- multiple contributors;
- one driver/lead;
- dashboards;
- recurring work;
- approval;
- operational automation;
- exceptions.

Mental model:

> **I move from doing everything to steering how work is done.**

---

# H3 — Director / Owner

A director understands:

- organization as a graph;
- decision traceability;
- automation maturity;
- sensors;
- tensions;
- statistics as indicators;
- multi-level consequences;
- governance;
- human-agent delegation;
- when to keep validation and when to automate.

Mental model:

> **I can delegate without losing visibility or authority.**

---

# H4 — System owner / architect

A system owner understands:

- fractality;
- parent/child repair;
- permissions versus intelligence;
- root authority;
- observability;
- rollback;
- repair versus rebuild;
- sensor quality;
- criticality;
- multi-view;
- rule revisability.

Mental model:

> **The system must remain able to inspect, correct, and transform itself without silently destroying its own integrity.**

---

# Practical human loop

```text
something happens
→ I am informed
→ I understand why
→ I decide or act
→ the system records it
→ affected people are informed
→ the system checks what happened
→ I can revise the decision later
```

---

# Key cultural shift

The main transformation is not:

> “use more software.”

It is:

> **move from manual execution toward conscious pilotage.**

The maturity path is:

```text
manual
→ assisted
→ proposed
→ approved automation
→ trusted automation
→ periodic review
```

No level is morally superior. The correct level depends on context and trust.
